## 2. 物理问题的统一约定

所有问题都写成 **一维定态薛定谔方程**（原子单位制，ħ = m = 1）：

```
    Ĥψ = Eψ,      Ĥ = −½ d²/dx² + V(x)
```

统一约定（写在 `physics/spectrum.py` 顶部，全项目遵守）：

| 约定 | 取值 | 为什么重要 |
|---|---|---|
| 能量 | 无量纲 **E**（Hartree） | 论文常用波数 k 当“能量”，k² = 2E；不换算就会整体错 √2 倍 |
| 归一化 | **∫|ψ|²dx = 1** | 物理标准；评估 overlap 的前提 |
| HHL 归一化 | max|ψ| = 1 | 论文用这个；`to_hhl_normalization` 负责换算 |
| 符号 | 首尾非零端取正 | 波函数整体符号无物理意义，不统一会导致 overlap 变 0 |

已实现的问题：

| 问题 | 势 | 精确能量 | 参考解来源 |
|---|---|---|---|
| `harmonic` | ½x² | n + ½ | 解析（Hermite 多项式递推） |
| `infinite_well` | 0 (0<x<L) | n²π²/(2L²) | 解析（正弦） |
| `finite_well` | −V₀ (|x|<a) | 无闭式解 | Numerov + 打靶 |
| `hydrogen` | −1/|x| | −1/(2n²) | 解析（广义 Laguerre） |

## 3. 参考解为什么必须“自己先信得过”

神经网络解的好坏，**只能**相对参考解衡量。参考错 → 所有精度结论作废。
因此 `physics/` 有一条硬性要求：**每个参考解必须用第二种独立方法再算一遍**。

| 问题 | 方法 A（给出答案） | 方法 B（交叉检验） | 实测偏差 |
|---|---|---|---|
| 谐振子基态 | 解析 e^{−x²/2} | Numerov 打靶 | ΔE ≈ 1.4e-12 |
| 谐振子第 1/3 态 | 解析（奇宇称） | Numerov 打靶 | ΔE ≈ 1e-10 |
| 有限深方势阱 | Numerov | 同法换网格 | ΔE ≈ 1e-12 |
| 无限深方势阱 | 解析 | V₀=2000 深阱近似 | ΔE ≈ 5e-3 ~ 4e-2（**物理差异**，非数值误差） |

实测表格见 [`runs/physics_verification.txt`](../runs/physics_verification.txt)：**10/10 通过**。

### 工程上踩过的坑（都已修复，记录在案）

1. **稠密矩阵对角化不可行**：`numpy.linalg.eigh` 是 O(N³)，N=4000 要两分钟。
   → 改用 **Numerov 打靶**（O(N) ~ O(N·二分步数)），同样的网格几秒钟出结果。
2. **单向积分不稳定**：波函数在经典禁区指数增长的那一支会淹没真实解。
   → **双向积分 + 中点拼接**，并用 ψ′/ψ 连接条件定拼接比例。
3. **奇宇称态拼接陷阱**：奇宇称态在中点恰好为 0，若起爆点离中点只有一步，
   整条曲线会是全零。→ 起爆点退到第 3 个网格点。
4. **三对角 Jacobi 的邻居耦合项**：手写稀疏旋转时若漏掉 `e_{k+2}` 的贡献，
   误差不会立刻爆炸，而是每轮累积——看起来“能跑”，结果全错。
   → 最终采用**已验证的稠密 Jacobi**（与 `numpy.linalg.eigh` 逐元素比对）。

## 4. 三条实验线（对应 HHL 论文的三组结论）

### 实验一 · 正则化网络（有监督回归）→ `scripts/exp1_regularized_network.py`

* **输入** `(x, E)`：能量作为第二输入通道；
* **训练集**只覆盖 E ∈ {0.5, 1.5, 2.5, 3.5} 的精确本征函数；
* **核心问题**：网络能否在 E = 2.0 这样的**中间能量**上插值出本征函数？
* **对照**：同样的插值误差，经典线性插值能达到多少？论文结论是“等价”，
  本项目把它作为**必须报告的基线**，而不是只报网络自己的数字。

### 实验二 · 非正则化 PINN（无监督）→ `scripts/exp2_unregularized_pinn.py`

* 去掉全部标签，默认用残差 + 归一化 + Rayleigh 商（无边界项：波函数在 ±6 已衰减）；
* 另有“仅残差”“可学习 E”“随机能量采样”等对照，见 `docs/experiments.md`；
* **关键评测陷阱**：PINN 很容易出现“能量很准、波形是杂波”——与真解正交的污染
  分量对 Rayleigh 商是一阶不敏感的。因此指标里 `overlap`、`inf_norm` 与能量
  **必须同时报告**（`solver/evaluate.py` 的文档专门说明）；
* 与实验一的同样是本征态问题，用于对比“有监督 vs 无监督”的收敛难度。

### 实验三 · 数据同化（物理 + 少量观测）→ `scripts/exp3_data_assimilation.py`

* 只在 k 个随机点上有带噪观测（k = 0 / 16 / 64），其余靠物理；
* 这是最接近“真实量子设备上做测量”的设定：HHL 论文的正则网络在真实硬件上
  也面临“查询次数有限 + 噪声”的问题；
* 预期趋势：k 增大 → overlap 提升、能量误差下降；k=0 时退化成实验二。

### 实验四 · 后验证书（A 线，进行中）→ `solver/certify.py` + `scripts/certify_saved.py`

* **问题**：上面三个实验都只报告“与参考解的误差”，无法在无真解时判断解是否可信；
* **做法**：对网络给出的 ψ 计算 Rayleigh 商 η 与 H_h 残差 ‖r‖，用
  Temple/Weinstein 界给出双侧误差条；用 Sturm 计数**验证**单态区间，
  用 Davis–Kahan 界给出本征函数夹角上界；
* **为什么重要**：能量误差是波函数误差的二阶量；只报能量会系统性高估精度。
  证书不读取参考解，因此也能审计“把真实 E 喂进残差”“用解析态做 deflation”
  这类泄漏；
* **证书引导滤波**（`solver/filtering.py`）：PINN 残差被高频分量主导，
  而 H_h 把它们放大 1/h²。把 ψ 投影到前 K 个正弦模式、扫描 K、取证书
  宽度最小者，可在不读参考解的情况下把不可认证的输出变成紧界
  （原型：残差 0.361→0.0051，宽度 0.260→5.22e-5，而 ψ 的相对 L2 改变
  只有 8.8e-5）；证书认证的是滤波后的 ψ，论文必须同时报告两列；
* **状态**：方法与 24 个证书/滤波单元测试已完成；多种子扫描正在跑，
  包含率/紧度与 go/no-go 判定待其结束后写入。
  设计、数学与判定标准见 [`certification.md`](certification.md)。

> 训练脚本需要 PyTorch（当前环境为 torch 2.12.0+cpu）。安装后即可运行：
>

## 5. 损失函数的组织方式

`solver/losses.py` 把损失拆成**可独立测试的项**，每项一个函数：

| 组 | 项 | 公式 | 用在哪 |
|---|---|---|---|
| 物理 | `residual` | mean[(−½ψ″ + Vψ − Eψ)²] | 实验二/三 |
| 物理 | `energy` | Rayleigh 商 ⟨ψ|Ĥ|ψ⟩/⟨ψ|ψ⟩ | 实验二（变分项） |
| 物理 | `normalization` | (∫|ψ|² − 1)² | 全部无监督 |
| 物理 | `boundary` | ψ(∂Ω)² 之和 | 方势阱 |
| 物理 | `orthogonality` | Gram 矩阵非对角元平方和 | 依次求激发态 |
| 数据 | `supervised` | ‖ψ − ψ_target‖² | 实验一 |
| 正则 | `l2` / `curvature` | ‖θ‖² / ∫|ψ″|² | 抑制过拟合/高频噪声 |

权重默认值集中在 `LossWeights`；返回分项损失的训练路径必须通过
`TrainConfig.term_weights` 把权重传给 `Trainer`（否则 `Trainer` 只会做
`sum(terms)`，权重静默失效——工程记录第 13 条）。另提供 `grad_balance` 做梯度
RMS 均衡，这是 PINN 训练的常见失败点（残差项量纲大，会淹没边界项）。

## 6. 指标体系（为什么不止看能量）

| 指标 | 定义 | 能发现什么 |
|---|---|---|
| `energy_abs_err` | |E_model − E_ref| | 体能量是否对 |
| `overlap` | |⟨ψ_model|ψ_ref⟩| / (‖·‖‖·‖) | 波形整体是否对 |
| `inf_norm` | max|ψ_model − ψ_ref| | 最坏点偏差（局部伪影） |
| `residual_rms` | ‖Ĥψ − Eψ‖ 的 RMS | 是否真的满足方程 |

`tests/test_evaluate.py` 专门测了这个陷阱：给“真解 + 0.8 倍正交噪声”，断言
`overlap < 0.99` 且 `inf_norm > 0.1`——保证评测器**不会**把杂波当成好解。

## 8. 已知边界与后续可做

* **训练已跑，但仍是小规模**：torch 2.12.0+cpu 下三个实验均已执行，实验二/三
  的 3 种子重复扫描正在收尾。只有一维、四个势，且实验二的结论仍在随扫描更新——
  引用数字前先看 [results.md](results.md) 顶部的版本说明。
* **只做了一维**：多维/氢原子的三维问题是自然扩展，`physics/spectrum.py` 已留
  `hydrogen_radial` 作为径向一维的入口。
* **未接入 QNN**：HHL 论文的量子线路分支（PennyLane）没有复现，`build_hhl_network`
  给出的是经典等价结构；接 PennyLane 只需替换 `forward`。
* **谱方法基线走的是 Numerov**：本意是用有限差分特征值，但受限环境里自己实现的
  三对角迭代反复出错（见第 3 节），最终选择“正确性优先”，复用了已验证的 Numerov。
* **证书目前只对离散 H_h 严格**：连续算子的严格扩展需要 O(h²) 截断误差界，
  尚未完成；简并/近简并需要子空间版 Temple 界，当前实现会拒绝认证。
  这是 A 线最需要在论文里写清楚的边界（见 [`certification.md`](certification.md) §4）。
* **证书在真实 PINN 上可能“不可认证”而不只是“宽”**：早期小模型
  能量/overlap 很好（0.5006 / 0.99999），但 H_h 残差 L2=1.12，超过
  Temple 二次条件允许的上限，证书只能判 `valid=False`。这不是证书 bug：
  二阶差分把网络的高频噪声放大了 1/h²。把离散残差直接纳入训练
  （实验五）后，同一问题变为可认证（宽度 0.260），但宽度仍是真实误差的
  上万倍。证书引导滤波可以把宽度再降近 4 个数量级（5.22e-5），但这认证的
  是滤波后的 ψ，不是网络原始输出——A 线因此定位为“评测协议/失败模式
  检测”，而不是高精度认证。详见 [`certification.md`](certification.md)
  §5.5–5.6。
