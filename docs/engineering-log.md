# 工程问题记录

本文档记录本项目开发过程中**真实遇到并解决的问题**。每条都遵循同一个格式：
症状 → 根因 → 修复 → 现在的防回归手段。

---

## 1. 稠密矩阵对角化太慢，参考解生成卡死

**症状**：用 `numpy.linalg.eigh` 在 N=4000 网格上求本征对，单次约 2 分钟；
参考解生成脚本连续跑几十分钟无输出。

**根因**：`numpy.linalg.eigh` 是 O(N³)。而一维问题完全不需要全谱。

**修复**：改用 **Numerov 积分 + 打靶法**（`physics/numerov.py`），复杂度 O(N·迭代次数)。

**防回归**：`tests/test_numerov.py` 与解析谱逐项比对；
奇宇称态在对称网格上应**精确**（误差 < 1e-8），这是离散格式的强不变量。

---

## 2. 单向 Numerov 积分不稳定

**症状**：从一端积分到另一端，波函数在远端指数发散。

**根因**：二阶差分方程有两个解，一增一减；沿任何方向积分，增长的那支都会淹没衰减的那支。

**修复**：**双向积分** —— 从左右两端各积分到中点，按 ψ′/ψ 连接条件确定拼接比例。

**防回归**：`test_wavefunctions_orthonormal_and_shape`（Gram 矩阵非对角元 < 5e-2）。

---

## 3. 奇宇称态得到全零波函数

**症状**：前几个本征值正确，但某些态的波函数整条曲线为 0。

**根因**：双向积分在“端点内第 1 个点在正好 2h 处”的那个网格点上起爆；
而奇宇称态在中点恰好为零，于是右侧整段从 0 开始递推，全为零。

**修复**：把起爆点退到**第 3 个网格点**（`ignite=3`），给递推留出非零初值。

**防回归**：`test_harmonic_all_states_close` 覆盖奇偶两类态。

---

## 4. 三对角 Jacobi 的“邻居耦合项”——最隐蔽的坑

**症状**：自己写的循环 Jacobi 一轮扫描后**非对角元全为零**，看起来完美收敛；
但特征值结果错得离谱。

**根因**：对三对角矩阵做 Givens 旋转时，`e_{k+1}` 会被 `e_{k+2}` 的贡献污染：

```
    正确：e_{k+1} ← cs·e_{k+1} − sn·e_{k+2}
    错误：e_{k+1} ← cs·e_{k+1}          # 看起来也收敛，但收敛到错误的矩阵
```

令人意外的是，用**显式矩阵** `GᵀTG` 逐个验证时，我的实现是对的；
问题出在把公式写成稀疏更新时，符号与下标反复对不上，且每次“看起来对”。
整个过程花了很大篇幅仍未收敛到可信实现。

**修复**：**正确性优先**——`symmetric_tridiagonal_eigh` 改为把矩阵展开成稠密
（N ≤ 400 时开销可接受），复用已验证的 `symmetric_eigh_jacobi`；
谱方法基线（`SpectralSolver`）也改为复用已验证的 Numerov 求解器。

**防回归**：`tests/test_eigen.py` 与 `numpy.linalg.eigh` **逐元素**比对（6/20/101 阶）；

**教训**：当“优化版本”反复与参考实现对不上时，先退回经过验证的实现，
把优化当作独立任务并配独立测试——不要让“性能优化”污染正确性。

## 5. 测试里的求积误差伪装成代码 bug

**症状**：`∫|ψ|²dx = 1` 的断言在 1e-8 量级失败。

**根因**：用梯形公式在有限区间上积分 `e^{-x²}·x²`，截断误差 + 网格误差约 1e-8 量级；
不是归一化写错了。

**修复**：测试里改用 **2 点 Gauss-Legendre 复合求积**，对解析解可达机器精度。

**防回归**：`tests/test_physics_spectrum.py::_gl_quad`。

---

## 6. 有限差分谱里混着“截断伪态”

**症状**：在 [−8, 8] 上离散谐振子，最低特征值约 −702（真实基态是 +0.5）。

**根因**：边界处 V(±8) = 32，一阶导数截断把它变成了一个极深的“伪势阱”，
产生大量负能量的伪本征态；真实能级夹在它们中间。

**修复**：这个现象的“正确解法”就是不依赖它——参考解用 Numerov 打靶，
它天然只给出物理本征值。稠密特征分解只用于**验证小规模矩阵**。

**防回归**：`tests/test_eigen.py::test_harmonic_hamiltonian_spectrum` 只断言
数值实现的**自洽性**（单调性、正交归一、残差），不对伪态做物理断言。

## 7. 测试运行器在受限环境下不可用

**症状**：`pip install pytest` 失败（`Permission denied` 写临时目录）。

**修复**：写了一个 `tests/minipytest.py`，提供 pytest 的常用子集接口
（`approx`/`raises`/`fixture`/`skip`/`importorskip`/`mark.skipif`），
同一批测试文件既能用 pytest 跑，也能用它跑。

**过程中修的两个自身 bug**：
1. 用 `vars(module).items()` 迭代时缓存夹具会修改 `vars`，触发 "dictionary changed size during iteration"；
   改为 `list(vars(module).items())`。
2. 模块级 `importorskip`（无 torch）抛出 `_Skip` 时没有被捕获，直接中止整轮测试；
   现在按模块粒度捕获并打印 `SKIP 整个模块`。

## 8. 评测器的“能量准但波形错”陷阱

**问题**：如果只用 Rayleigh 商当指标，PINN 可能给出“能量对、形状全错”的解也被判为成功。

**防回归**：`tests/test_evaluate.py::test_orthogonal_noise_is_caught`。

## 9. 环境里没有 torch：训练脚本如何处理

**问题**：三个实验脚本依赖 PyTorch，但沙箱环境里没有。

**处理**（有意设计）：
* `solver/backends.py` 提供 `has_torch()` / `require_torch()`，延迟导入；
* 训练脚本先检查，缺失时打印环境信息并返回**退出码 2**（明确区别于“运行失败”）；
* 与 torch 相关的测试用 `importorskip` 跳过，而不是 fail；
* 文档明确标注“实验未运行”，不编造数字。

**教训**：受限环境下，**如实报告“没跑”**比给出一个假数字更有价值。

## 10. 能量曲线一直抖动，但训练其实是收敛的

**症状**：谐振子基态训练 5000 步，能量在 0.482 ~ 0.527 之间来回摆（±0.5%~2%）。
第一反应是"学习率太大"或"损失项没平衡"。

**诊断**：把模型固定住、只变化采样点，重复 30 次估计 Rayleigh 商：

| 采样方式 | 估计值标准差 |
|---|---|
| 2500 个均匀随机点 | **1.9%** |
| 2500 个等距网格点 | **1e-8** |

**根因**：``Losses.energy`` 用 `mean(...)` 当积分近似。当样本是每步重采样的随机点时，
这个 mean 就是**蒙特卡洛估计**，其噪声 ∝ 1/√N。N=2500 时标准差恰好 1.9%——
与观察到的抖动幅度完全吻合。这不是训练不收敛，是**估计量本身在抖**。

**修复**：能量项改用固定的等距网格（残差项继续随机采样，它本质是逐点均方，
随机采样反而避免在固定网格上过拟合）。能量误差从 4.16e-3 降到 **8.73e-4**（4.8 倍）。

**教训**：调参之前先确认**指标本身有没有噪声**。我一开始去接梯度均衡，
虽然它没有坏处，但真正的问题在估计量的方差上——诊断花的时间比调参少得多。

## 11. 求激发态时投影算子用错，能量算成 7.9（真值 1.5）

**症状**：给 PINN 加正交约束求谐振子第一激发态，能量收敛到 7.91、overlap 只有 0.117。
第一反应是"正交约束没生效"或"训练不够"。

**诊断 1**：先单独验证投影算子本身——把解析的 ψ₁ 投影，结果应是 ψ₁ 本身：

    project(ψ₀) 的范数 ≈ 0        ✓ 基态被消掉
    project(ψ₁) 与 ψ₁ 的 overlap = 1.0  ✓ 激发态被保留

算子没问题。于是问题在"求导"环节。

**诊断 2**：把解析的 ψ₁ 喂给 `energy_projected`，看它返回什么：

    期望 1.500000，实际 1.250000

1.25 = 1.5 × (5/6)，是个可疑的固定比例。拆开看各分量：

    |dψ/dx| 在中点：未投影 1.062，投影后 0.531   ← 正好一半

**根因**：我把**导数也投影了**。

    P = I − |ψ₀⟩⟨ψ₀| 是投影到 "与 ψ₀ 正交的函数" 这个子空间
    约束 ⟨ψ|ψ₀⟩ = 0 的切空间基是 **ψ₀′**，不是 ψ₀
    用 ψ₀ 去投影 ψ′ = 减掉了一个本不属于该空间的分量

数值上 `⟨ψ₀, ψ₁′⟩ = 0.707 ≠ 0`，所以这一步把 ψ₁′ 削掉了相当一部分，
动能项跟着变小，Rayleigh 商就偏了。

**修复**：`energy_projected` 只在求导**之后**对波函数本身做投影，导数保持原样：

    psi   = model(x)
    dpsi  = grad(psi, x)      # 先求导
    psi_p = projector(psi)    # 只投影 ψ
    E = (½∫dpsi² + ∫V·psi_p²) / ∫psi_p²

对 `residual_projected` 则无需特别处理：Ĥ 与常数投影矩阵可交换，
`ĤPψ − EPψ = P(Ĥψ − Eψ)`，先作用 Ĥ 再投影即可。

修复后解析态精确复现 1.5，训练得到的激发态 E = 1.5111（相对误差 0.74%），overlap 0.9965。

**教训**：加约束前先想清楚"约束作用在哪个空间上"。
约束 `⟨ψ|φ⟩=0` 限制的是 ψ 的**取值**，不是 ψ 的**导数**——
投影算子和微分算子不可交换，除非投影的基恰好也在切空间里。

## 12. Numerov 打靶只有偶宇称态偏差 1e-3——中点用了单侧差分

**症状**：交叉校验一直是 10/10 通过，但谐振子的小误差呈现奇怪的规律：

| n | 旧实现 \|ΔE\|（N=2001） | 奇偶 |
|---|---|---|
| 0 | 1.70e-3 | 偶 |
| 1 | 3.2e-11 | 奇 |
| 2 | 4.2e-3 | 偶 |
| 3 | 2.3e-10 | 奇 |

奇宇称态精确到 1e-10，偶宇称态却只有 1e-3。测试容差 5e-3 让这个偏差"合法"通过了。

**根因**：打靶法在中点比较两段的对数导数时，用的是**单侧差分**

    ψ′(x_m)/ψ(x_m) ≈ (ψ_m − ψ_{m−1}) / (h·ψ_m)

截断误差 O(h)。奇宇称态在对称区间的中点恰好 ψ(x_m)=0（数值上极小），
匹配条件退化为对 ψ′ 的约束，反而绕开了这个一阶误差；偶宇称态没法绕开，
于是误差 ∝ 1/N（实测 N=501→16001 严格减半）。

**修复**：积分越过中点一步，改用**中心差分**

    ψ′(x_m)/ψ(x_m) ≈ (ψ_{m+1} − ψ_{m−1}) / (2h·ψ_m)

匹配误差降到 O(h²)。同一网格 N=2001 上：

| n | 修复后 \|ΔE\| |
|---|---|
| 0 | 5.1e-12 |
| 2 | 1.2e-10 |

**防回归**：`tests/test_numerov.py::test_even_states_are_second_order_accurate`
（N=2001，四个态的误差都必须 <1e-8）。旧的 5e-3 容差测试保留，作为整体健全性检查。

**教训**：测试"通过"不等于精度到位。容差是为了容纳合理的离散误差，
不是用来掩盖 O(h) 与 O(h²) 的差别；对称性带来的"恰好精确"最容易让人误判求解器质量。

## 13. 多种子扫描暴露的两个"目标函数不一致"问题

**症状**：用 `run_seed_sweep.py` 重跑实验二（5000 epochs，width=128，depth=4）时，
结果与旧单次运行严重不符：

| 配置 | 旧单次结果 | 新扫描（3 个种子） |
|---|---|---|
| 仅残差损失 | E=0.6047，overlap 0.9859 | E=8.61 / 16.07 / 9.60，overlap 0.47~0.53 |
| + Rayleigh（随机点） | E=0.5042，误差 4.16e-3 | 唯一的种子 E=0.5564，误差 5.64e-2 |

旧结果并非"种子运气好"，而是代码里有两个独立的目标函数不一致。

### 13.1 `Trainer` 忽略损失权重，残差项可以靠 ψ→0 作弊

`exp2` 构造了 `LossWeights(residual=1, energy=10, normalization=100)`，
但 `step_fn` 返回的是**未加权分项**，而 `Trainer.fit` 在非梯度均衡路径下执行的是

    loss = sum(info["terms"].values())        # 旧代码

权重从未被应用。归一化项实际按 1 生效，残差项（≈1）与它同量级；
而 ψ≡0 让残差严格为 0、归一化只付出 1 的代价，于是优化器找到了
"输出恒为零"的平凡解。评测时 `evaluate_model` 会把 ψ 重新归一化，
零输出的形状噪声被放大，才出现 E=8.6、overlap=0.47 这种数字。
训练损失收敛到 1.000 正是 `(∫ψ²−1)² = 1` 的签名。

**修复**：`TrainConfig` 新增 `term_weights`，`Trainer.fit` 用它做加权和：

    loss, weights = self._weighted_sum(info["terms"])

`exp2` 传入 `term_weights=weights.as_dict()`；历史记录里的 `weights`
现在如实反映 residual/normalization/energy = 1/100/10。

### 13.2 早停只看未归一化残差，会回滚到平凡解

`exp2` 的 `validation()` 只返回 `losses.residual(...)`，同样对 ψ 的整体
缩放不敏感：训练初期 ψ≈0 时残差最小，best checkpoint 就被锁在最初几百步。
即使损失权重修好，早停仍会把它回滚到平凡解。

**修复**：验证损失改成与训练目标同口径的加权和
（残差 + 100·归一化 + 10·Rayleigh），并在固定网格上计算。
这样"ψ 很小"要同时支付归一化罚项，不可能再靠缩小整体幅度取胜。

### 13.3 顺带修正的网格间距

`np.linspace(-6, 6, 2500)` 的实际间距是 `12/2499`，不是 `12/2500`。
`Losses.dx` 原先用后者，给积分型损失引入 4e-4 的相对偏差；
实验三的 `[0,1]`、2000 点网格同样如此。两处都改成 `L/(N−1)`。

**验证**：修复后先跑 2000 epochs 的单种子冒烟测试：

| 配置 | E_model | 相对误差 | overlap |
|---|---|---|---|
| Rayleigh + 固定网格 | 0.500937 | 1.87e-3 | 0.99998 |
| 仅残差（E 固定 0.5） | 3.038 | 5.08 | 0.672 |
| 仅残差（E 可学习） | 4.038 | 7.08 | 0.546 |

后两行在 2000 epochs 时仍未收敛（验证损失还在下降），需要 5000 epochs
的多种子结果才能下结论；但网格配置已经回到 1e-3 量级，说明修复有效。

**防回归**：`tests/test_train.py::test_term_weights_are_applied`
直接断言 `term_weights={"a":10,"b":1}` 时总损失为 12 而不是 3。

**教训**：损失项的"权重"必须只有一个生效路径。把权重存进 `LossWeights`
却让另一条代码路径 `sum(terms)`，等于给了一个静默失效的配置项；
这类 bug 不会让测试变红，只会让结果在换种子后崩掉。
早停指标也必须与被优化的目标同口径——否则"最好的模型"可能是
目标函数根本不想要的那个解。

## 14. 正交约束的残差项喂了随机点，投影矩阵却按固定网格构造

**症状**：准备把激发态从 n=1 扩到 n=2/3 时，逐行检查 `exp2` 的 `step()`，
发现投影分支下这行：

    x = torch.tensor(rng.uniform(*DOMAIN, N_COLLOCATION).reshape(-1, 1), ...)
    ...
    residual = losses.residual_projected(net, x, e_res, potential, project)

而 `project` 的实现是

    coeff = basis.T @ psi * losses.dx
    return psi - basis @ coeff

`basis` 是 `(N, K)` 的解析参考态**在固定 `energy_grid` 上**的值；
`basis.T @ psi` 要求 `psi` 的第 i 行对应 `energy_grid[i]`。
随机配点的行顺序与网格毫无关系，这个矩阵乘法实际是在把
不同位置的值线性组合——投影不仅没有移除低阶态，还引入了随机混合。

同一条 `step()` 里，`energy_projected` 和 `normalization` 都用
`energy_grid` 或 `x_norm`，只有残差项用了随机点。因此旧的 n=1 结果
（0.74%）是“在错误投影下仍然碰巧收敛”，不能作为 n=2/3 的基础。

**修复**：正交约束启用时，残差项也使用固定 `energy_grid`：

    if orthogonalize:
        x_np = energy_grid
    else:
        x_np = rng.uniform(*DOMAIN, N_COLLOCATION)

非正交配置不受影响（仍用随机配点）。固定网格可能带来过拟合，
但正交投影**必须在同一张网格上定义**，这是正确性的前提。

**教训**：凡是“矩阵/基向量 + 网格”的代码，必须同时检查
“矩阵是按哪张网格构造的”和“调用处传的是哪张网格”。
形状相同（都是 `(2500,1)`）不代表语义相同；这类 bug 不会报错，
只会让约束静默失效。

## 15. Temple 界的两个分母写反了（证书曾经无效）

**症状**：在检查“证书是否为真界”时，用两能级模型做了反例。取
H = diag(0, 10)，ψ 为 |0⟩ 与 |10⟩ 的 50/50 混合：η = 5、‖r‖² = 25。
旧实现给出

    lower = η − ‖r‖²/(η−a) = 5 − 25/6 ≈ 0.833，

而真值 λ₀ = 0。也就是说，旧代码声称“λ₀ ≥ 0.833”，把真值排除在外。
这个 bug 在谐振子测试里没暴露，因为各能级等距：η−a ≈ b−η，两种写法数值接近；
在无限深阱的精确态上又因为 r≈1e-11 而必然包含。

**根因**：Kato–Temple 定理的配对是

    η − ‖r‖²/(b−η) ≤ λ ≤ η + ‖r‖²/(η−a)，

即**下界用上邻居、上界用下邻居**。直觉上的“对称写法”是错的：
η > λ 时污染只能来自上方，η < λ 时只能来自下方。旧代码恰好写反。
定理还有前提 `‖r‖² < (b−η)(η−a)`，旧代码也没有检查。

**修复**：

* `temple_bounds` 改用正确配对，并在前提不成立时抛 `ValueError`；
* `certify_eigenpair` 捕获该错误，返回 `valid=False`，reason 明确写
  “残差相对谱隙太大”，不再给出一个看似精确实则无效的区间；
* 新增回归测试：两能级反例 + 前提检查 + 公式核对；
* 修正 `docs/certification.md` §2.2、`docs/literature.md` §3 的公式。

**教训**：单元测试只证明了“实现符合我以为的公式”，没有证明“我以为的公式是对的”。
对“严格界”类代码，必须用一个能让错误公式给出**明显违反真值**的反例做测试；
等距谱（谐振子）是最坏的测试用例，因为它让错误公式也能通过。

## 16. Sturm 计数的扰动用了绝对尺度，在大 h⁻² 下永远退不出去

**症状**：证书引导滤波的测试里，`discrete_eigenvalue(X, V, 0)` 在
`x = linspace(0, 1, 401)`、`V = 0` 上抛
`ValueError: Sturm 计数遇到退化的主元序列`。二分第一次取的 shift 恰好等于
`diag[0] = 1/h² = 160000`，此时自由粒子第 200 个本征值精确等于该值，LDLᵀ
首主元为零。

**根因**：容差本身是按 scale 缩放的（`tol = 1e-13·max(1,|shift|,max|diag|)`，
这里 `tol ≈ 1.6e-8`），而旧的重试增量是绝对量级、最大也就 1e-8 上下：
不仅小于容差，前几步（1e-13 量级）连 `shift = 1.6e5` 的 ULP（≈3e-11）都
跨不过去，浮点值根本没变。六次重试因此全部被判为“零主元”。

**修复**：按**相对**尺度扰动且每次放大 10 倍：
`shift + scale·1e-11·10^(attempt−1)`，第一次不扰动。第 2 次就比
`tol = 1e-13·scale` 大两个量级，远大于 ULP。同时把语义写清楚：shift 恰好
落在谱点上时“小于/小于等于”在浮点下不可区分，实现约定为**上移**后计数
（即返回 ≤ shift 的计数），区间验证必须把边界放进谱隙里。

**教训**：容差是相对量时，扰动增量也必须是相对量；否则“放大重试”只是
在同一个浮点格点附近打转。测试里必须包含“阈值恰好等于某个浮点可表示的
本征值”这类边界输入——随机点和等距谱都碰不到它。

## 17. 用“证书宽度最小”选截断阶数，会把激发态滤成基态

**症状**：`guided_filter` 的第一版直接取“Temple 宽度最小的 K”。对基态
没问题；对第一激发态的带噪输出，K=1 的纯正弦截断给出一个比正确态**更窄**
的证书——因为它把 ψ 滤成了基态，而基态本身当然可认证。

**根因**：宽度衡量的是“这个函数离**某个**本征态有多近”，不衡量“离
**哪个**本征态近”。最小化宽度是一个无约束优化，它可以靠改变答案来
降低误差条。

**修复**：扫描前先对原始 ψ 做一次 `isolate=True` 的证书得到
`state_index`；扫描中只接受认证到**同一个** `state_index` 的候选。扫描
记录里额外写 `same_state` 字段，被拒绝的候选在报告里仍然可见。

**教训**：任何“用误差条做模型选择”的准则，都必须同时固定被估计的对象。
后验证书能证明“接近某个本征对”，但不能替你决定是哪一个；状态一致性
必须作为显式约束写进选择准则，而不是事后解释。

## 18. 端点非零时 Rayleigh 商没有下界，能量项把训练推向发散

**症状**：证书同口径训练的多种子扫描里，无限深阱基态（`infinite_well_0`）
三个种子全部发散：残差 7e4~3.8e5，能量从 2.4e3 到 7.2e4，证书
`state_index` 跑到 21/27/120。同一次扫描的有限深阱也坏了一个、谐振子坏了
一个。但同样的脚本在谐振子上此前跑出过宽度 0.216 的正常结果。

**关键线索**：日志里的总损失出现**负值**（-1e4 ~ -4.7e4）。四项损失
（残差、归一化、边界、能量）都是平方或 Rayleigh 商，加权和不可能为负。
把保存的 ψ 代回公式，发现 `energy` 项是 -985：V=0 的无限深阱算出负能量。

**根因**：能量项把**含非零端点**的 ψ 直接代入二阶差分：

    E = h Σ ψ_j (H_hψ)_j / (h Σ ψ_j²)

这只是 Dirichlet 二次型当 ψ_0 = ψ_N = 0 时的写法。端点非零时，求和丢掉
了边界项（分部积分会产生 ψ_0ψ_1/h² 量级的贡献），二次型因此**没有下界**：
把端点放大就能让 E → −∞。优化器当然选择这条路。谐振子上 h 大、边界
惩罚很快压住端点，所以问题被掩盖；无限深阱 h = 5e-4，1/h² 大 144 倍，
一发散就回不来。

**修复（第一版，错的）**：把所有差分都改成“端点置零”。结果 3000 epoch
后 overlap 只有 0.64、E=2.86——残差在边界处看到的是人为跳变，永远压不
下去。**残差必须用真实端点**：它衡量的是“网络输出这个区间上的光滑函数”
离方程多远；端点值由 `boundary` 项负责。

**修复（最终版）**：`losses.discrete_dirichlet_terms` 只对**能量项**用
Dirichlet 延拓（端点置零）的二次型；残差保留真实端点。能量因此恒
≥ λ₀(H_h)，且与证书的 `discrete_rayleigh_quotient` 同口径。修复后同一
配置（3000 epoch、128×4、seed 0）回到 E=0.500014、overlap=0.999998、
残差 0.361、证书宽度 0.260——与 bug 前的结果一致。

**回归测试**：`test_discrete_terms_energy_has_a_lower_bound_with_nonzero_endpoints`
用一个端点取 3 / −2 的 ψ 断言新能量 ≥ 4.9 且与 numpy 证书口径一致，同时
断言旧写法在同一 ψ 上给出负能量。

**教训**：从“带边界的 PDE”切到“离散矩阵 + Dirichlet 边界”时，边界值
不是小的装饰项——它在二次型里带 1/h² 系数，能改变整个优化问题的有界性。
任何“能量/Rayleigh”项都必须显式声明边界约定，并用一个边界明显非零的
测试钉死它。

## 19. 双精度特征值求解器的绝对误差比证书宽度还大

**症状**：无限深阱第一激发态的滤波证书宽度约 1e-10，但 `contains`
判定失败：区间不包含“独立参考本征值”。三份 run 全部如此，偏差稳定在
5e-10，看起来像 Temple 公式又错了。

**诊断**：把三方数值摆在一起（h = 1/2000，‖H_h‖ ≈ 1.6e7）：

| 来源 | λ |
|---|---|
| LAPACK `eigh_tridiagonal` 本征值 | 19.739192567806 |
| 本项目 Sturm 二分 | 19.739192567533 |
| LAPACK 本征向量的 Rayleigh 商 | **19.739192567337** |

LAPACK 的绝对误差上界是 `eps·‖H_h‖ ≈ 1.6e-9`，Sturm 的主元容差
（`1e-13·‖H‖ ≈ 1.6e-6`）也把可分辨的 σ 精度限制在 1e-10 量级。两者都
**比证书宽度大**。Rayleigh 商把本征向量的角度误差平方掉，误差 ~1e-19，
是唯一在这个尺度上可信的参考值。

**修复**：`independent_discrete_ref` 不再返回 LAPACK 的本征值，而是用它
的本征向量算 Rayleigh 商（仍然不依赖本项目的 Sturm 代码）。文档里同时
报告 `Δsturm`（Sturm 值与参考值之差），这个量本身就是求解器精度的诊断。

**教训**：“独立参考”不等于“另一个库的默认输出”。在紧证书（宽度接近
机器精度 × 矩阵范数）的尺度上，必须使用误差**已知且更小**的参考——这里
是 Rayleigh 商，而不是另一个特征值求解器。

测试/报告时也不要拿连续解析值当参考：H_h 与连续算子相差 O(h²)≈1e-6，
同样比 1e-10 的证书宽度大。

## 20. “无泄漏”的 certs5 基态 run 其实用了参考能量

**症状**：准备把 9 个 `certs5` 基态 run 与 `certs/learned0` 的 3 个一起
当作 §5.1 的 12 个 leakage-free 样本时，对照代码发现
`exp5_certificate_training.energy_value()` 在 `learned_energy=False` 时
**无条件**返回 `ref.energy`——不管目标是基态还是激发态。`certs5` 的配置
只给 n=1 加了 `--no-energy`，基态没有加 `--learned-energy`，因此 9 个
“无泄漏”run 的残差里全部是参考能量。

**为什么这是泄漏**：残差 `H_hψ − Eψ` 的零点包含所有本征态；把真实的
目标本征值 E 告诉优化器，等于从谱里挑出目标态。§5.4 自己把
`residual_energy = reference` 列为泄漏组，§5.1 却把同一批 run 称为
leakage-free——定义和实现不一致。`--no-energy` 只关掉 Rayleigh 项，
并不改变残差里的 E，因此也不是无泄漏。

**修复**：`certs5` 基态改为 `--learned-energy`（E 是可学习标量），
epochs 从 3000 提到 10000。实测：
* 谐振子基态：E=0.50002、overlap=1.0000，3000 epoch 即可；
* 无限深阱基态：E=4.9329（相对误差 3.8e-4）、overlap=1.0000；
* 有限深阱基态：3000 epoch 停在 E=−7.24、overlap=0.37（非本征态）；
  10000 epoch 才回到 E=−48.967、overlap=0.99996、残差 0.319。

**教训**：泄漏审计必须先审计自己的配置。“无监督”不是由 `--no-energy`
这类开关的名字决定的，而是由**每一次前向计算实际读取了哪些量**决定的。
把泄漏类型写进每个 run 的 JSON（`residual_energy`）是对的，但汇总脚本
必须按这个字段筛选，不能按组名假设。

## 21. 可学习的 E 在深阱上根本没收敛，证书却仍然有效

**症状**：`certs5` 的有限深阱基态（`--learned-energy`）在 10000 epoch 后
Rayleigh 商正确（−48.9657/−48.9685/−48.9661，与离散参考差 ~1e-2），
overlap 0.99995–0.99998，但**可学习标量 `E_learned` 停在
−9.79/−9.70/−9.88**，离真值 −48.97 差 39。

**这不是“E 收敛慢一点”**：用保存的 ψ 直接算 H_h 残差

```
‖H_hψ − E_learned ψ‖₂ = 28.3   (三个种子都是)
‖H_hψ − η ψ‖₂        = 1.2–2.6 (η = Rayleigh 商)
```

也就是说训练目标里的残差项实际值约 28，根本没有被最小化；优化器是靠
Rayleigh 项（权重 10）和归一化项把 ψ 推到基态的，E 只跟着残差项走，
Adam 在 10000 步内只把它从 1.0 拖到 −9.8。证书用的是 η 而不是
`E_learned`，所以证书仍然有效——这掩盖了训练目标不自洽。

**为什么是方法问题**：残差 `Hψ − Eψ` 对 E 的梯度是 `−2⟨ψ, Hψ−Eψ⟩`，
在 ψ 接近本征态时 ≈ 2(E−η)，本身是二阶小的；而 E 只有一个标量、和
网络参数共享 lr，深阱的 η≈−49 与初值 1.0 相差 50，收敛尺度完全不同。
继续加 epoch 或调 lr 都只是碰运气。

**修复方向**（已实现，见工程记录 22）：不要把 E 当自由参数，直接用当前 ψ 的
Rayleigh 商 `η(ψ)=⟨ψ,H_hψ⟩/⟨ψ,ψ⟩` 代入残差。这样
`Hψ−ηψ` 自动与 ψ 正交，残差项的二阶条件与证书口径一致，也不需要
给 E 单独调学习率。代价是每步多一次矩阵向量乘（本项目已有）。
若保留可学习 E，必须把 `|E_learned − η|` 作为诊断量写进结果，
并在 `|E_learned − η| > ‖r‖` 时判为“训练目标未满足”。

**教训**：证书认证的是 (ψ, η)，不是训练时声明的损失。一个 run 可以
“证书有效 + overlap 很好 + 学习到的 E 完全错误”三者同时成立；论文里
不能把 `learned_energy_value` 当作能量估计，也不能因为证书有效就
推断训练目标被满足了。

## 22. Rayleigh 商残差：修好了训练目标，也顺手修好了有限深阱的证书

**做法**：`--rayleigh-energy` 把残差里的 E 换成当前 ψ 的离散 Rayleigh 商
（Dirichlet 延拓、`detach`）。三重好处：

1. `H_hψ − ηψ` 对 E 是最优的（∂/∂E ‖Hψ−Eψ‖²=0 ⇔ E=η），残差项不可能
   再被一个不收敛的自由标量拖住；
2. 训练目标与证书口径**完全一致**——证书算的就是同一个 η；
3. 少了一个超参（E 的学习率），也少了一个必须审计的诊断量。

`detach` 是安全的：在极值点 η 对 ψ 的一阶导数为零，保留梯度只会让能量
项与网络参数争梯度。

**结果**（`certs5_rayleigh`，3 势 × 3 seed × 10000 epoch）：

| 势 | learned-E 组滤波宽度 | Rayleigh 组滤波宽度 | 原始可认证 |
|---|---|---|---|
| 谐振子 | 1.6e-5 – 4.3e-4 | 2.7e-5 – 9.3e-4 | 2/3（不变） |
| 无限深阱 | 9.87e-12 | 9.87e-12 | 2/3（不变） |
| 有限深阱 | 1.87 – 2.72 | **0.37 – 0.73** | 1/3 → **3/3** |

有限深阱改善 3–4 倍，与**泄漏**的 reference 组（0.34–0.63）几乎持平。
这才是 B 线真正有说服力的结论：泄漏的收益来自“让残差里的 E 接近真值”，
而这件事不泄漏也能做到。

**过程中的一个 bug**：第一版 `rayleigh_quotient` 里写
`v[1:-1] * p_i`，v 的形状是 (N,1)，直接乘会广播成 (N−2,N−2) 矩阵，
Rayleigh 商算出 76507（300-epoch 冒烟测试抓到）。改成
`v.reshape(-1)[1:-1]` 后得到 0.500048。教训：`torch` 的广播不会报错，
形状错了也照样能算出一个“数”。

## 23. 可学习 deflation 找到了激发态，但一个种子跳过了目标态

**症状**（§5.7 的 n=1 失败）：固定参考 E、无正交时，谐振子/有限深阱在
10000 epoch 后仍停在基态或混合态（overlap 0.003–0.77）。

**做法**（C 线最小原型）：先跑同 seed 的 Rayleigh 基态并保存 ψ₀；训练
n=1 时每一步做 `ψ ← ψ − ⟨φ,ψ⟩φ`，φ 是**训练输出**归一化后的基态（不是
解析解）。保存的是投影后的 ψ，证书认证它。

**结果**（3 势 × 3 seed）：8/9 落到 n=1 且被证书确认；谐振子滤波宽度
3.4e-5–3.6e-5（与基态同量级）、无限深阱 1e-10（K=2，平凡）、有限深阱
0.36–0.57。`deflate_overlap` 全部 ≤1.1e-16，投影在浮点精度内正交。

**失败的种子**：`harmonic_1/seed2` 得到 E=2.4889（≈5/2）、overlap(ψ₁)=0.109
——它**跳过 ψ₁ 直接停在 ψ₂**。deflation 只移除了 ψ₀，正交补里能量最低的
是 ψ₁，但 Adam 从随机初值出发可以越过它。这不是证书的问题，证书如实
报告 `state_index=2`。

**教训**：证书回答“你找到的是某个本征态”，不回答“你找到的是目标态”。
必须把 `state_index == target_state` 作为独立的一列（`state_matches_target`），
否则“证书有效 + 9/9”会掩盖“其中一个答非所问”。若要多态主张站住，
deflation 需要链式（φ₀, φ₁, …）或子空间版本，而不是只投掉最低一个。

**链式版本（n=2，同日补跑）**：`--deflate-from` 改为可重复，求 n=2 时
按 Gram–Schmidt 依次投掉训练得到的 ψ₀、ψ₁。9 个 run 中 8 个落到 n=2
（谐振子滤波宽度 4.4e-5–4.7e-5、无限深阱 3e-10–1.9e-8、有限深阱
0.50–0.68）。失败的是 `harmonic_2/seed2`：上一级 `harmonic_1/seed2` 落到
的是 ψ₂，于是这一级把 ψ₂ 投掉、留下 ψ₁，网络停在 n=1。**分级实验必须
逐级检查 `state_index`，不能只看最后一级是否“认证有效”**——证书对
“答错的题”同样有效。

## 24. 二维默认关闭傅里叶特征：随机高频投影在 2D 学不动

**症状**：`exp6`（二维谐振子，[-3,3]²，41×41，1500 epoch）开启

## 25. 二维训练塌缩到 ψ≡0：损失在零解处有驻点

**症状**：方阱 3000 epoch 后 `norm2≈1e-4`、E=35.85、overlap 0.946
（形状对但幅度趋零），证书宽度巨大。

**根因**：残差项 `mean((Hψ − ηψ)²)` 与边界项都含 ψ² 的公共因子，ψ→0
时损失→0——零解是**精确驻点**。一维没暴露是因为 Rayleigh 项和归一化项
的权重恰好把它推开。

**修复**：损失全部作用在 `u=ψ/‖ψ‖`（`scale = sqrt(cell·Σψ²)`），并在
保存前统一归一。损失对尺度不变，零解被排除（分母置 `clamp_min(1e-30)`）。
修复后方阱 6000 epoch：E=9.868338（误差 1.4e-6）。

## 26. 二维软边界惩罚压不到机器精度，改用硬 Dirichlet 掩码

**症状**：方阱 41×41、3000 epoch、`w_boundary=100`：E=10.6（真值 9.87）、
残差 5.6，证书宽度 0.1 量级，训练看起来"没学会"。

**根因**：二维 Dirichlet 边界只占 O(1/N) 的配置点；均方损失里边界项的
权重被内部点稀释，`(p[0,:]²).sum()/norm2` 的梯度不足以把边界压到 1e-2 以下，
而五点 Laplacian 对边界值极其敏感（1/h² 放大）。

**修复**：网络输出乘以掩码 `(x−a)(b−x)(y−a)(b−y)`。这是**给定的边界
条件**，不是参考解，不构成泄漏。修复后同一配置 E=9.8645、残差 1.3e-2；
6000 epoch、81×81 时 E=9.868338（对 λ_h 误差 3e-13 经滤波后）。

**教训**：硬约束把"训练难点"变成"表示空间限制"，代价是网络在边界附近
的表达力——对本征函数（边界为零）没有损失。

## 27. 二维惯性计数给出过一个假证书（简并态，宽度 9.5e-11）

**症状**：`exp7` 第一次跑，方阱第一激发态（二重简并，|E₁−E₂|=1.6e-14）
返回 `valid=True`，Temple 宽 9.5e-11。

**根因**：`count_eigenvalues_below_2d` 在主元退化时按 `scale·1e-11·10^k`
扰动 shift 重试；扰动把 shift 推过了简并对中的一个本征值，于是
`count(σ_hi) − count(σ_lo) = 1` 被"验证"为单态。零点几皮米的谱隙在
双精度下本来就不该被当成可分。

**修复**：`_resolution_floor(grid) = 1e-9·scale`，
`scale = max(1, ½(2/hx²+2/hy²)+max|V|)`。验证出的谱隙低于下限时返回
`valid=False`，理由写"低于双精度惯性计数分辨率"。一维
（`certify._resolution_floor`）补了同一道闸门，一维既有结果全部不变。

**教训**：验证流程里的**重试**是危险的原语——它会把"无法判定"变成
"判定成功"。重试之后必须再检查一次结论是否仍然成立（这里是谱隙 vs 分辨率）。

## 28. `dst1_2d` 对二维数组调了一维 DST

**症状**：`filter_dirichlet_2d` 抛 `IndexError: too many indices for array`。

**根因**：写成 `dst1(np.apply_along_axis(dst1, 1, values).T).T`——`.T` 之后

`tests/test_certify2d.py::test_dst1_2d_is_involution` 锁住对合性。

## 35. 区间算术里，行列式递推 35 步就瞎，pivot 比值能走到底（2026-10-28）

**症状**：实现定向舍入计数时，先用 Sylvester 惯性的教科书形式 d_k = (a_k−sigma)d_{k−1} − b²d_{k−2}，
在区间里跑。结果从第 35 到 45 步起，d_k 的区间包含 0，符号不可判，计数永远失败。
363 个扫描 shift（N=2001，3 个势）上无一例外。

**诊断**：不是实现错，是数学性质。d_k 在谱的体量尺度上剧烈抵消——它交替变号，
在谱的“体量”附近几乎为零。区间每步放大一点点，几十步后相对宽度超过 1。
这是区间算术中“包围盒”的经典失效，不是浮点精度问题：换成更高精度也只会把
失败点往后推，不会消失。

**修法**：改用 LDL^T 的 pivot 比值递推 q_1 = a_1 − sigma, q_k = (a_k − sigma) − b²/q_{k−1}。
它不是另一种展开，而是**不同的一组中间量**：当 pivot 可分时，b²/q 是对
a_k − sigma 的小修正，区间不会暴涨。代价是每个节点一次除法，且必须处理
q 跨零——那正是要拒绝的情形。

**结果**：361/363 认证，两个拒绝都在扫描最后一个 shift 上（该 shift 在双精度里
恰好等于本征值），拒绝时报出出问题的 pivot 下标 999。单次 5 ms，浮点版 0.4 ms。

**教训**：在区间算术里，“同一个量”的不同算法不是等价的选择。先在小规模上量
相对宽度随步数的增长，比事后调试计数结果便宜得多。凡是递推里出现相消的，
区间版本就得换中间变量。

## 36. 连续算子的界不需要正则性，但需要挑对求积（2026-10-28）

**背景**：论文原来把“认证对象是离散的”列为局限，理由是标准路线
（O(h²) 显式常数、或椭圆问题的同伦包围）需要网络给不出的逐点正则性界。

**发现**：上界那一侧根本不需要。min–max 给出 lambda_1(H) <= R(u) 对**任何**
u 属于 H^1_0 成立；P1/Q1 插值后的采样函数在单元上是连续的、边界上为零，
所以它在 H^1_0 里。于是插值本身不需要常数——残差里没有插值误差项，
因为 Jensen 不等式那一侧我们根本没有用。代价只有求积。

**两个坑**：
1. **刚度项必须用有限元的 1/h，不是差分的 1/h²**。最初照抄差分对角元，
   所有界都偏大一个量级，看起来“保守”，实际是错的。
2. **势能项的求积只对多项式精确**。谐振子、box、以及把跳点当单元端点的
   有限深阱是多项式次数 <=2，5 点 Gauss 精确；但**没人保证使用者给的势
   满足这个前提**。所以代码同时用 3 点和 5 点算，相对差超过 1e-11 就拒绝。
   写测试时故意把 kink 放在单元内部——第一次偏移只放了 1e-4，kink 落在
   单元 2% 处，两个 Gauss 规则的差刚好在阈值以下，测试假通过；改成偏半格
   才真正抓住。**测试要测的是“能不能抓到”，不是“大概率能抓到”。**

**副产品（反例）**：有限深阱 N=4001 时跳点落在节点上，节点采样把 −50 写成 0，
离散基态能量被推到连续值**之上**（高 3.7e-3）。N=1000…1011 上六次在上、
六次在下，误差到 1.4e-2 且不单调。这不是 bug，是格式不变分相容的必然结果
（间断势的五点格式在跳点附近只有 O(h)，且误差符号取决于对齐方式）。

**归因**：一开始我把 N=4001 的高估笼统写成“洞把势抬高了”。写落盘脚本时顺手做了
对照——**同一张网格**，只把恰好落在跳点上的那个节点从“井外”改成“井内”
（0 → −50），其余全不动：λ_h 从 +3.67e-3 变到 −3.73e-3，**跨过真值 7.4e-3**。
所以整个误差就是这一个格点的取值，两种约定没有哪个更准。这比“O(h) 且符号不定”
的定性说法强得多，也更难被审稿人挑：它把误差归到了可复现的单点上。
脚本 `scripts/continuous_bound.py --alignment` → `runs/continuous_bound/alignment.json`
（含每张网格的 offset/h、节点取值、两种约定下的误差）。**教训**：凡是写“误差来自 X”
的因果句，都要有一个只改 X 的对照实验；没有对照就不要写机制。
box 相反：sin(theta) <= theta 给出 lambda_j^(h) <= lambda_j 对所有 j 和 h 成立，
两端都严格。**“离散证书”和“连续证书”之间隔着一个变分相容性前提，
不能靠更好的 factorization 补上。**

**教训**：想给“连续算子”做认证时，先问哪一侧能由变分原理免费拿到；
剩下的一侧才是真问题，而且往往不是数值问题而是格式问题。

## 37. 二维本征值的认证 bracket：中点、拒绝与“最后一个已验证的区间”（2026-10-28）

**背景**：一维 bracket 靠对认证计数做二分。二维可分离势的计数已经能认证
（Kronecker 和），照理二分一下就该有二维的 bracket，但第一版每次调用都返回
`None`。

**坑一：二分里遇到拒绝不能当成失败。** 计数在 shift 靠近某个本征值时必然拒绝
（区间的两个端点分不开）。第一版让二分把“计数拒绝”当作整体失败、直接返回
`None`，于是二分永远在第一次碰到拒绝时放弃——而它要收敛到的正是拒绝发生的地方。
改成 `break`，保留**最后一次验证成功的区间**：bracket 的宽度就正好停在计数
分辨率上，这正是我们想要的语义（“能证到这里为止”，不是“证不了”）。

**坑二：中点取 0.5 会踩在提示值上。** 二分从 `hint`（通常是稠密求解器给的本征值，
已经精确到 1e-13）附近起步；取算术中点时，`0.5` 恰好落在 hint 上，计数在这个
shift 上拒绝，于是每轮只推进一格，宽度卡在 2e-3 不动。改用黄金分割点
`lo + 0.6180339887498949*(hi - lo)`，永不与端点重合（除非区间退化），
宽度立刻降到 1e-11 量级。

**坑三：宽度的解释要写对。** 最后得到的 1.4e-11 不是“我们算得多准”，而是
**计数能分辨多细**：在 bracket 的端点处，pivot 或 Kronecker 和的区间刚好还能
定符号。所以论文里说的是“认证 bracket 的宽度”，不是“本征值的误差”。

**结果**：谐振子（2D）1.4–6.0e-11、box（2D）3.7e-10–2.5e-9（41–101 点/边）。
表 `tab:continuous` 里二维可分离势的 λ_h 因此是 bracket 中点，而不是 Lanczos 值；
只有不可分的非谐势仍是稀疏分解本征值，论文里明确标注。

**教训**：二分 + “可拒绝的判定”这种组合，拒绝点就是答案所在——实现要保留最近
一个可用的区间，而不是把拒绝当异常往上抛。另外，任何用固定比例取点的迭代
（中点、黄金分割）都要检查它是否可能落在提示值/边界上。

## 38. 全文一致性审计：四处"上一版为真"的句子（2026-10-28）

**背景**：定向舍入与连续界加进来之后，只改了 §6；跑了一次全文只读审计
（读 `main.tex` + 全部 `sections/*.tex`，再加载 `runs/` 的 JSON 逐条算术核对），
发现论文里还留着四句"写的时候是真的、现在不是"的话。这类错误比算错更危险：
审稿人一眼就能看到自相矛盾。

**四句**：
1. 讨论节"剩余的唯一问题是浮点分辨率，定向舍入能消除它"——① 分辨率下限本来
   就是**声明出来的安全余量**，不是定理；② 定向舍入不消除它，只是让余量以下
   的计数变成有理由的拒绝；③ 精确数据上的拒绝不止一种：跳过某个态的试验子空间
   是因为维数与计数不符（结构原因），根本不是 floor。`runs/degeneracy2d/subspace.json`
   里有原文可查。
2. "方阱的 bracket 两端都严格"——表里显示的是**认证 bracket 的中点**，下界由
   sinθ≤θ 给出的是离散本征值，不是中点。正确说法：中点可以换成 bracket 的下端点，
   两者相差 2.5e-9，比边距 8e-4 小五个数量级，结论不变。
3. "只报残差会把这两个态的精度高估七个数量级"——实测基态残差 3.34e-12、
   被拒激发态 4.02–4.78e-12，**只差 1.4 倍**。正确的说法更有力：残差完全分不开
   这两类态，而证书的答案是"激发态根本没有定义"。
4. "瑞利商用与计数相同的定向舍入机制"——代码里三项积分的**累加**用了区间，
   单元积分与 V 的求值没有。量级 1e-16 相对，不改任何数字，但"严格"只能说到
   "精确算术下严格"。

**教训**：
- 一次能力升级之后，要扫**全文**，不只是新增的章节。被改掉的旧句子会以
  "我们没有……"的形式留在引言、摘要、讨论、结论里，成为最显眼的自相矛盾。
- 引用的每个"数量级"都要能由落盘数据直接算出；"七个数量级"是凭印象写的，
  实测差 1.4 倍。凡是句子里有倍数，先算再写。
- 严格性是一个**链**：区间求和 + 浮点单元积分 ≠ 严格。审稿人只要顺着代码看
  一层就能发现；主动在正文里点明缺口，比被问出来好得多。

## 39. 按 CPC Guide for Authors 做投稿合规改造（2026-10-29）

**背景**：作者要"直接投稿"，于是把存下来的 CPC Guide for Authors 抽成文本逐条比对
（`~/.claude` 之外的临时文件，不入库）。发现稿件在内容上没问题，但**格式硬性项**
有多处不符；这些如果留到投稿系统里，编辑部会在技术审查阶段退回。

**逐条改动**：
1. **摘要 556 词 → 209 词**。Guide 上限 250 词。改法不是删信息，而是把
   "我们做了什么"压成主句，把实现细节（传输引理、截断阶选取、0.95/1.01 分辨率
   扫描）留给正文。顺带解决了摘要跨页、关键词被挤到第 2 页的排版问题。
2. **参考文献改数字制**。原稿是 authoryear + `elsarticle-harv`，Guide 明确要求
   正文用 `[n]` 且按出现顺序编号。改为 `\documentclass[...,number]` +
   `elsarticle-num`。唯一的 `\citet{cances2020}` 在数字制下会报
   "Author undefined"，改成 `Canc\`es et al.~\cite{cances2020}`。
   踩坑：删掉 `main.aux` 后 latexmk 会在 `\citation` 写入之前跑 bibtex，
   `.bbl` 变成 0 字节；手工 `pdflatex → bibtex → pdflatex ×2` 才恢复。
3. **Program Summary 换成 CPiP 模板字段**：`CPC Library link ... (to be added by
   Technical Editor)`、`Licensing provisions: MIT license (MIT)`、
   `Supplementary material`、三段各自标注 "(approx. 50--250 words)"、
   末尾 `References:`。原来 `Nature of problem` 只有 39 词，低于 50 词下限，
   扩写到 61 词。
4. **新增声明段**：CRediT（两作者同等贡献）、Funding（Guide 规定的"无基金"标准句）、
   Data availability、以及 Guide 要求的
   "Declaration of generative AI and AI-assisted technologies…"。
5. **Highlights**：单独文件 `paper/highlights.docx` + `.txt`，5 条，最长 78 字符
   （上限 85）。
6. **文章类型定为 CPiP**（带 Program Summary、代码归档、MIT 许可），
   cover letter 相应改写。
7. **投稿包**：`scripts/make_submission_archive.py` 生成
   `paper/submission/nn-schrodinger-certify.zip`（816 文件 / 10.8 MB），
   `paper/submission/README-SUBMISSION.md` 列出上传清单与系统内要填的项。

**教训**：
- 期刊的 "Guide for Authors" 是**可执行的规格**，不是背景资料。摘要词数、关键词
  个数、highlight 字符数、参考文献制式、声明段落，都是能一条条勾的硬指标；
  写完就自查，比被编辑部退回来便宜。
- 排版问题和合规问题是同一个问题的两面：摘要从 556 词压到 209 词之后，
  首页与 Program Summary 的跨页问题一起消失了。
- 每次动 `main.aux`/`main.bbl` 之后都要确认 `.bbl` 非空；0 字节的 `.bbl`
  在 PDF 里只表现为一条 natbib 警告，很容易被当成无害。
